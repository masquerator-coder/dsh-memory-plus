## 1. UI 设计原则

| 原则               | 含义                                       |
| ------------------ | ------------------------------------------ |
| **透明可控**       | 用户能看见系统记住了什么，能随时修改或删除 |
| **用户主权**       | 用户编辑的优先级最高（credibility=1.0）    |
| **渐进披露**       | 默认只显示核心信息，高级配置折叠           |
| **危险操作需确认** | 删除、重置等操作二次确认 + 可撤销          |
| **实时反馈**       | 异步操作（抽取、聚合）有进度提示           |
| **不打断对话**     | 所有设置可在对话进行中修改，无需重启       |

### 3.2 人格（soul.md）

**目的**：编辑 Agent 人格配置，控制注入行为。

```
┌─────────────────────────────────────────────────────────────┐
│  人格设置                                   [保存] [重置]    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  注入模式：  ○ 仅核心人格（推荐）  ○ 完整注入               │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ # Soul                                               │   │
│  │                                                       │   │
│  │ ## 核心人格（始终注入）                                │   │
│  │ - 你是一位严谨但温暖的研究助理                         │   │
│  │ - 你倾向于先给结论，再给依据                           │   │
│  │ - 你不确定时会明确说"我不确定"                         │   │
│  │                                                       │   │
│  │ ## 交互风格（始终注入）                                │   │
│  │ - 默认简洁，用户要求详细时才展开                       │   │
│  │ - 使用中文，除非用户切换语言                           │   │
│  │                                                       │   │
│  │ ## 边界（始终注入）                                    │   │
│  │ - 不主动提及自己是 AI                                  │   │
│  │ - 不代替用户做最终决策                                 │   │
│  │                                                       │   │
│  │ ## 扩展设定（按需检索，不默认注入）                    │   │
│  │ - 详细背景故事见 memory:scope=agent:soul#extended     │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  预览：注入后占用 312 token（核心部分）                      │
│                                                             │
│  [从文件导入]  [导出为 .md]  [查看扩展设定]                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**交互**：

- 编辑器为 Markdown 支持（语法高亮、实时预览）。
- 「预览」显示实际注入系统提示的 token 占用。
- 「查看扩展设定」弹出抽屉，展示从记忆检索的扩展内容。
- 保存时校验：核心人格不能为空，token 超限时警告。
- 用户编辑后立即热重载，下一轮对话生效。

**边界情况**：

| 情况       | 处理                             |
| ---------- | -------------------------------- |
| 文件不存在 | 显示模板，引导创建               |
| 格式错误   | 高亮错误行，禁止保存             |
| Token 超限 | 警告但允许保存，提示会挤占上下文 |
| 并发编辑   | 检测文件 mtime，冲突时提示合并   |

**边界情况**：

| 情况                 | 处理                                       |
| -------------------- | ------------------------------------------ |

| 删除程序记忆         | 提示可能影响 Agent 技能                    |
| 删除用户画像核心事实 | 提示 user.md 将同步更新                    |
| 大数量操作           | 异步执行 + 进度条                          |

### 6.2 实时事件订阅

```typescript
// 订阅后端事件
ctx.on('memory/event', (event) => {
  switch (event.type) {
    case 'fact/created':
      memoryStore.appendFact(event.fact)
      break
    case 'fact/superseded':
      memoryStore.updateFact(event.oldId, { status: 'superseded' })
      memoryStore.appendFact(event.newFact)
      break
    case 'consolidation/completed':
      memoryStore.fetchStats()
      break
    case 'profile/updated':
      profileStore.load()
      break
  }
})
```

### 6.3 乐观更新

```typescript
async function updateFact(id: string, update: FactUpdate) {
  const previous = memoryStore.getFact(id)
  // 乐观更新
  memoryStore.patchFact(id, update)
  try {
    await api.updateFact(id, update)
  } catch (error) {
    // 回滚
    memoryStore.patchFact(id, previous)
    toast.error('更新失败：' + error.message)
  }
}
```

### 7.1 保存冲突处理

| 场景                         | 处理                                               |

## 11. 总结

**核心设计要点：**

1. **总开关置顶**：一键启用/禁用，状态清晰。
2. **七大模块**：概览、人格、用户画像、记忆管理、提示词注入、备份恢复、高级设置。
3. **用户主权**：user.md 编辑回写原子事实，credibility=1.0 永远胜出。
4. **透明可控**：每条记忆可溯源、可编辑、可删除。
5. **危险操作保护**：二次确认 + 可撤销 + 建议备份。
6. **实时同步**：后端事件推送，UI 实时更新。
7. **与 Cordis 集成**：通过 `ctx.settings.registerTab` 注册，插件卸载自动清理。

这套 UI 让记忆系统从「黑盒」变为「透明可控的工具」，用户能看见、理解、修改系统记住的一切。
